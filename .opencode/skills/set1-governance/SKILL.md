# Set 1 Governance

Use the smallest approved specialist set and no more than two concurrent subagents. Keep planning, exploration, UI/UX, implementation, data/API, testing, debugging, review, security, readiness, and release responsibilities separate.

Require explicit approval before implementation, application edits, installs, migrations, external writes, Canva calls, permanent model changes, Git writes, destructive actions, paid services, or deployment.

Prefer deterministic local validation before MCP or premium-model use. Allow at most one approved premium retry for one unresolved issue. Never select a fallback model, paid route, Kimi, Grok/xAI, ElevenLabs, audio, or voice automatically.

Audit only concise decisions, model IDs, commands, file references, results, approvals, and unknowns. Never record credentials, headers, environment values, private records, or hidden reasoning.
